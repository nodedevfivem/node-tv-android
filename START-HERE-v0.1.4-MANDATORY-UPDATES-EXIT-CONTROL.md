## Update notification flow
1. Publish a **full GitHub Release** (not merely a Git tag or Actions artifact) in `nodedevfivem/node-tv-android`.
2. Release must be published, NOT draft/prerelease, with `vMAJOR.MINOR.PATCH` tag, e.g. `v0.1.4`.
3. Attach the 3 files documented below, generated by an official permanently signed GitHub Actions build.
4. Include `<!-- NODETV_UPDATE_MODE: MANDATORY -->` in the release description; REQUIRED for older v0.1.2 and v0.1.3 clients. For v0.1.4+ clients mandatory is also the default. To make a future release optional for v0.1.4+ clients only use `<!-- NODETV_UPDATE_MODE: OPTIONAL -->` (older clients may not recognize OPTIONAL).
5. On Android, the app checks GitHub's public `/repos/nodedevfivem/node-tv-android/releases/latest` API on app launch/return and every 30 minutes (10-minute minimum interval between automatic checks). It requires a valid newer version and a downloadable official APK/checksum before activating the update notice.
6. A required update blocks watching; it cannot install APKs without Android's normal permission and explicit installation approval. If the latest release is missing assets or GitHub is unreachable, the app cannot discover an unseen update.
7. Once detected, mandatory state is saved across launches. While offline, a previously confirmed mandatory update remains required until installation; DETAILS opens GitHub and UPDATE NOW retries.

## Official GitHub Actions build
- Upload **contents of UPDATE ONLY ZIP** to the existing repository root (not the ZIP itself), preserving directories including `.github/workflows/` and `app/`.
- Push the changes to the repository's main branch; then go to **Actions → NODE TV Android APK** and open the resulting run or select **Run workflow**.
- The workflow automatically builds a debug test APK when release signing secrets are missing (file `NODE-TV-TEST-ONLY.apk`). This is NEVER an official release.
- Official signing requires FOUR existing repository Actions secrets: `NODETV_KEYSTORE_B64`, `NODETV_STORE_PASSWORD`, `NODETV_KEY_ALIAS`, `NODETV_KEY_PASSWORD`. NEVER upload private signing assets or plaintext credentials to repository, releases, or ChatGPT.
- If secrets are present and valid the workflow assembles release, verifies APK signature via `apksigner` and packages an Actions artifact named `NODE-TV-Android-APK` containing:
  ```text
  NODE-TV.apk
  NODE-TV-Android-v0.1.4.apk
  NODE-TV-Android-v0.1.4-SHA256.txt
  ```
- Unzip the Actions artifact on your computer, then attach all three files to a **GitHub Release**, tag `v0.1.4`, title and description supplied in `GITHUB-RELEASE-v0.1.4.txt`.
- **Do not publish before validating** the build and in-place update on a phone. Official APK name is `NODE-TV.apk` (never DEBUG).

## Test procedure (real Android phone)
1. Install a signed official build, start playback of a VLC-fallback stream and an ExoPlayer stream.
2. In landscape, tap near the edge → EXIT FULLSCREEN appears without pausing; tap it → portrait and same channel.
3. In landscape, tap center → pauses AND exit control appears; tap center again → resumes.
4. Left vertical swipe adjusts brightness, right vertical swipe adjusts media volume. Confirm EXIT is not triggered by swipes.
5. Enter/exit fullscreen repeatedly on HBO/Cinemax or other channels to confirm v0.1.3 video-scaling corrections.
6. For mandatory-update verification: install an **older official permanently signed build**, then publish a **newer signed release** with three correct assets and mandatory marker. Relaunch the older app with internet: UPDATE REQUIRED should block viewing. Tap UPDATE NOW, approve installation; favorites should be retained if same app id and signing certificate.
7. Temporarily disconnect network after confirming a mandatory update: required gate persists. Without ever seeing a release, offline users are not falsely gated.
8. Confirm package `net.nodedevelopment.nodetv`, versionName `0.1.4`, versionCode `5`, and Android 8.0+ compatibility.
